# 📏 07 · 长上下文与 MoE（混合专家）

> 两个让大模型「更便宜地更大」的关键方向：拉长上下文（能力边界）、MoE（参数扩大但推理省）。

---

## 一、长上下文（Long Context）

### 为什么难？
注意力复杂度 $O(n^2)$，n 从 4K→128K→1M，计算与显存爆炸。且位置编码需外推。

### 关键技术
1. **位置插值（Position Interpolation, PI） / NTK-aware RoPE**：把训练位置的旋转频率重新缩放，使未见过的长位置「映射」回已训练范围，平滑外推。
2. **稀疏/滑窗注意力**：局部窗口 + 全局 token，降低复杂度（Mistral 的 Sliding Window）。
3. **分段/稀疏模式**：Longformer、BigBird 等。
4. **推理侧**：PagedAttention + KV 量化，支持百万级 KV。

### 本质判断
长上下文≠真理解长文本。**「大海捞针」测试**显示，很多模型对中间信息（lost in the middle）利用率低。长上下文是「容量」问题，理解质量还需数据/训练配合。

## 二、MoE（Mixture of Experts）⭐

**思想**：把前馈层（FFN）换成**多个专家子网络 + 路由（Router）**，每个 token 只激活其中少数几个专家。

- 总参数大（容量大），但每 token 计算量小（只过 k 个专家）→ **参数量与算力解耦**。
- 代表：Mixtral 8x7B（8 专家，每 token 激活 2 个，实际效果≈14B 但推理成本≈12B 以下）。

### 路由机制
- Top-k 路由：token 选分数最高的 k 个专家
- 负载均衡损失（Load Balancing Loss）：防止所有 token 都挤少数专家（「专家坍缩」）
- 专家容量（capacity）：每专家处理 token 上限，超容则丢弃/缓冲

### 优点 / 代价
| 优点 | 代价 |
|------|------|
| 同等算力下更大容量 | 显存占用仍大（要存所有专家） |
| 推理成本随激活专家数 | 路由不均、训练不稳定 |
| 适合大规模扩展 | 部署/通信复杂（专家并行） |

---

## 三、高频追问

**Q1：MoE 为什么能「大参数低推理成本」？**
> 参数分布在多个专家，但路由只激活少数，单 token 计算量≈激活专家数 × 单专家，与总专家数无关；代价是显存要装下全部专家。

**Q2：为什么需要负载均衡损失？**
> 无约束时路由会偏好少数专家，导致大部分专家不被训练（坍缩），整体容量浪费。均衡损失促使 token 均匀分配。

**Q3：长上下文训练和推理的主要瓶颈分别是什么？**
> 训练：注意力 $O(n^2)$ 计算 + 显存；推理：KV Cache 随 n 线性增长的显存 + 单次前向时间。
