## 算法岗的「能力模型」

面试官评估算法候选人，通常按以下层次递进：

```
L1 概念层：知道 Transformer/RLHF 是什么
L2 原理层：能讲清为什么这样设计、代价是什么
L3 推导层：能写注意力公式、能推导 LoRA 参数量、能算复杂度
L4 实现层：能手撕 MHA/RoPE/LoRA 代码
L5 评判层：能对比方案、能针对场景选型、能指出局限
```

**本项目所有内容都按 L1→L5 组织**，并在每章附「高频追问」模拟面试官连环追问。

## 学习顺序建议

1. 先把 `01-Transformer` 吃透（**重中之重**，后面全依赖它）。
2. 再 `02-位置编码` 与 `03-预训练`（理解模型怎么「长出来」）。
3. 然后 `04-微调` + `05-对齐`（理解模型怎么「变好用」）。
4. 最后 `06/07/08`（工程与具体模型，用到再深究）。

---

## 本质判断（务必记住）

> **Transformer 不是「一个模型」，而是一套「可并行的序列建模范式」。**
> 它的跨周期价值在于：把「长程依赖 + 并行训练 + 可扩展」三者第一次统一。
> 任何说「Transformer 要被 X 取代」的论断，都要先看 X 是否同时满足这三点的替代。
