# 📈 05 · 大数据挖掘（推荐 / 搜索 / 广告 / 图挖掘）

> 工业界算法岗的「硬通货」。推荐/搜索/广告是 AI 公司营收核心，岗位多、要求扎实的工程+算法。

---

## 一、推荐系统经典架构
```
召回(百万→千) → 粗排(千→百) → 精排(百→十) → 重排(十→展示)
```
- **召回**：多路（协同/向量/热门），从全库快速缩小候选（双塔模型、ANN）
- **精排**：复杂模型（DeepFM / DIN / 树模型）精准打分
- **重排**：多样性、业务规则、去重

## 二、核心算法
- **协同过滤**：UserCF / ItemCF（基于行为相似）
- **矩阵分解**：隐向量建模
- **深度学习**：Wide&Deep、DeepFM、DIN（用户兴趣）、DIEN
- **向量召回**：双塔 + 向量检索（Faiss）

## 三、特征工程（仍关键）
- 类别特征（embedding）、数值特征（归一/分桶）、交叉特征
- 时序/行为序列特征、统计特征
- 特征重要性分析与清洗

## 四、评估与冷启动
- 离线：AUC、GAUC、召回率
- 在线：CTR、CVR、时长、留存（AB 实验）
- 冷启动：内容/用户冷启动策略、探索利用（Bandit）

## 五、图挖掘
- 图神经网络（GCN/GAT）、Node2Vec、社区发现
- 应用：社交推荐、风控关系网、知识图谱

## 六、高频追问
**Q1：为什么需要多路召回而不是一个模型？**
> 单模型难兼顾「全库覆盖+多兴趣」；多路互补（热门/协同/向量/实时）提升召回质量与覆盖，再靠精排择优。

**Q2：Wide&Deep 的 wide 和 deep 各解决什么？**
> Wide 记忆（历史高频共现），Deep 泛化（未知组合），结合兼顾记忆与泛化。

**Q3：推荐系统怎么处理冷启动？**
> 内容特征兜底、热度/探索策略、跨域迁移、Bandit 探索、用户注册信息利用。
