# 🐹 04 · Go（云原生与高并发服务）

> AI 公司的大量「中间件/网关/基础设施」用 Go：高并发、部署简单、云原生友好。Agent 平台、推理网关常用 Go。

---

## 一、核心考点
- **goroutine**：轻量协程（几 KB 栈），海量并发。
- **Channel**：CSP 并发模型，goroutine 间通信。
- **调度器（G-M-P）**：用户态调度，万级协程高效运行。
- **sync 包**：Mutex、WaitGroup、Once、原子操作。
- **GC**：并发三色标记，低停顿（适合服务）。
- **interface 与组合**：Go 的「多态」靠组合而非继承。
- **错误处理**：显式 error 返回（无异常）。

## 二、AI 结合点
- **AI 推理网关/代理**：高并发转发 LLM 请求、限流、鉴权、成本统计。
- **Agent 平台后端**：多 Agent 编排服务、任务队列、实时通信。
- **云原生基础设施**：K8s 生态（用 Go 写）、向量库/中间件。
- 框架：用 Gin / Fiber 写 REST，用 gRPC 做内部通信。

## 三、高频追问
**Q1：goroutine 和线程区别？**
> goroutine 由 Go 运行时调度、栈初始仅几 KB 可增长，单机可跑百万级；OS 线程更重（MB 级），受内核调度限制。

**Q2：Channel 关闭与遍历注意什么？**
> 向已关闭 channel 发送会 panic；用 `v, ok := <-ch` 判关闭；多生产者用 `close` 需谨慎（通常单处关闭）；for-range 自动在关闭后退出。

**Q3：Go 适合写 LLM 推理服务吗？**
> 非常适合做「网关/编排/代理」层（高并发、易部署）；但模型计算本身仍在 Python/C++ 推理引擎，Go 负责调度与转发。
