# 🧩 03 · 记忆系统与工具调用

> Agent 的「记忆」让它跨轮次连贯，「工具」让它真正动手。两个能力决定 Agent 是玩具还是生产力。

---

## 一、记忆系统（Memory）

### 短期记忆（Short-term）
- 当前对话上下文（prompt 窗口内）
- 实现：滑动窗口、最近 N 轮
- 瓶颈：上下文长度有限、长对话会丢信息

### 长期记忆（Long-term）
- 跨会话持久化知识
- 实现：
  - **向量库**（语义检索历史）
  - **摘要压缩**（定期把旧对话摘要，腾出空间）
  - **结构化存储**（数据库/知识库，按 key 检索）

### 记忆管理策略
- **写入**：重要结论/用户偏好显式存入长期记忆
- **检索**：按需从长期记忆拉取相关片段
- **压缩**：超长对话做摘要，保留关键信息

---

## 二、工具调用（Tool Use / Function Calling）⭐

**Function Calling**：用 JSON Schema 定义函数，LLM 输出「调用哪个函数 + 参数」，由外部执行并返回结果。

```
tools = [{
  "name": "get_weather",
  "description": "查询天气",
  "parameters": {"type":"object","properties":{"city":{"type":"string"}}}
}]
# 模型输出：{"name":"get_weather","arguments":{"city":"北京"}}
# 执行后把结果回灌给模型继续推理
```

**Tool Use vs Function Calling**：
- Function Calling：标准化（JSON Schema）、易实现、兼容 OpenAI API
- Tool Use：更灵活的工具描述、可并行调用多个工具、元数据更丰富
- 选择：简单场景 Function Calling；复杂工具系统/需并行 → Tool Use

---

## 三、工具路由与安全（⭐ 生产必问）

- **工具路由**：多个工具时，如何选对工具？靠工具描述质量 + few-shot + 必要时用「分类器/检索」先筛工具。
- **参数校验**：模型给的参数不可信，必须做 schema 校验、类型转换、边界检查。
- **安全**：
  - 危险操作（删库、发邮件）需**人工确认/权限控制**
  - 工具输出可能含注入（提示注入攻击），需隔离/清洗
  - 限制工具执行超时、资源、次数

---

## 四、高频追问

**Q1：如何优化 Agent 的工具选择准确性？**
> 清晰工具名/描述/参数示例、few-shot、按需检索缩小候选工具集、错误后反馈学习、必要时用小模型做工具路由分类。

**Q2：短期记忆不够怎么办？**
> 滑动窗口 + 摘要压缩 + 长期记忆检索；把关键事实显式提取存库，对话中按需拉取，而非全量塞上下文。

**Q3：怎么防御提示注入（Prompt Injection）？**
> 把工具返回内容当「不可信数据」隔离、不执行其中的指令、输出做清洗、高危工具加权限与人工确认、最小权限原则。

**Q4：工具调用失败怎么处理？**
> 重试 + 错误回灌给模型让其自我修正、备用工具、超时/资源限制、无法恢复时优雅降级并如实告知用户。
