# 🛡️ 05 · Agent 工程化与评估（从 Demo 到生产）

> 面试区分度极高的话题：**能跑 demo 的人很多，能上生产的人很少。** 本篇讲可靠性、可观测、成本控制与评测。

---

## 一、可靠性工程

- **超时与降级**：工具调用超时 → 重试/备用/降级回答，绝不卡死。
- **重试与指数退避**：对瞬时失败（API 限流）重试，避免雪崩。
- **熔断（Circuit Breaker）**：某工具/模型连续失败 → 暂时停用，保护系统。
- **最大步数/循环检测**：防 Agent 无限循环，超步数强制终止并说明。
- **输入/输出校验**：工具参数 schema 校验；模型输出格式校验（JSON mode / 结构化）。

---

## 二、可观测性（Observability）

- **全链路追踪**：记录每步 Thought/Action/Observation、token 消耗、耗时、调用链。
- **日志与回放**：出问题能回放整条轨迹定位（LangSmith / 自研 trace）。
- **评测数据集**：固化一批典型 case，每次改动能回归测试。

---

## 三、成本控制

- **模型路由**：简单任务用小模型，复杂任务才上大模型（如分类用 0.5B，推理用 70B）。
- **缓存**：相同 query 缓存结果；语义缓存（相似问题复用）。
- **上下文压缩**：去掉无关历史，省 token。
- **批处理 / 异步**：并发降低延迟与成本。

---

## 四、Agent 评估体系

| 层 | 评测什么 | 方法 |
|----|----------|------|
| 单工具 | 工具调用正确率、参数准确 | 单元测试 |
| 轨迹 | 步骤是否合理、是否走偏 | 人工/Trajectory 评测 |
| 结果 | 最终答案是否正确可用 | 任务成功率、LLM-as-Judge |
| 系统 | 延迟、成本、可靠性 | 线上监控 + AB |

常用基准：AgentBench、WebArena、ToolBench、GAIA。

---

## 五、部署架构（典型）

```
用户请求 → API 网关 → 意图识别 → Agent 编排器
                              ├── ReAct Agent（思考-行动-观察）
                              ├── 规划 Agent（任务分解）
                              ├── RAG Agent（知识检索）
                              └── 反思 Agent（质量校验）
支撑层：多路检索(向量+BM25) · 记忆(Redis滑窗+向量库) ·
       工具系统(MCP) · 模型路由+熔断 · 全链路追踪 · 文档ETL
```

---

## 六、高频追问

**Q1：Agent 上线最大的坑是什么？**
> 不可控性：长链路任一步失败/幻觉都影响结果；成本高且难预测；难评测。解法：全链路追踪 + 降级 + 回归评测集 + 成本监控。

**Q2：怎么做 Agent 的回归测试？**
> 固化典型任务集与「期望轨迹/结果」，每次改动跑回归；用 LLM-as-Judge 评质量；监控线上成功率/成本/延迟漂移。

**Q3：模型路由怎么设计？**
> 按任务复杂度路由：分类/抽取用小模型，推理/生成用大模型；用置信度/失败率动态调整；保证整体成本与质量平衡。
