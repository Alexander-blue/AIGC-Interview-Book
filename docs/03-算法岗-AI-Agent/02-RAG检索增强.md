# 📚 02 · RAG 检索增强生成（Retrieval-Augmented Generation）

> 当前**落地最广**的 Agent 能力。解决大模型「知识过时、易幻觉、不可溯源」三大痛点。面试几乎必问。

---

## 一、为什么需要 RAG？

LLM 的局限：训练数据有截止日期、私有知识不知、易编造。RAG = **生成前先「查资料」**，把相关资料塞进上下文。

> 本质：用「检索」补足 LLM 的「参数化记忆」短板，让回答**可溯源、可更新、可控**。

---

## 二、RAG 标准流水线

```
文档 → 切片(Chunk) → 嵌入(Embedding) → 存入向量库
                                      ↓
用户问题 → 嵌入 → 检索(Top-k) → 重排(Rerank) → 拼接上下文 → LLM 生成
```

### 1. 文档切片（Chunking）
- 固定长度 vs 语义切分（按标题/段落/句子边界）
- 重叠（overlap）避免切断语义
- 元数据保留（来源、时间、章节）便于过滤

### 2. 嵌入（Embedding）
- 把文本映射为向量，语义相近则向量相近
- 选模型：BGE、E5、OpenAI text-embedding 等（中文注意选中文强模型）

### 3. 检索（Retrieval）
- **稠密检索**（向量相似度，ANN 索引：HNSW/IVF）
- **稀疏检索**（BM25，关键词精确）
- **混合检索**（Hybrid = 稠密 + 稀疏，RRF 融合）← 效果最好

### 4. 重排（Rerank）
- 初检 Top-k（如 20）→ 精排模型（Cross-Encoder）重排 → 取 Top-n（如 5）
- 显著提升相关性

### 5. 生成
- 把「问题 + 检索片段」拼成 prompt，要求模型**只基于片段回答并标注来源**

---

## 三、进阶 RAG（面试加分）

- **Query 改写/扩展**：把口语问题改写为规范检索词；多query 分解复杂问题
- **Self-RAG**：模型自判「是否需要检索」「检索片段是否相关」
- **GraphRAG**：用知识图谱做全局摘要/社区检索，适合「总结整个文档库」类问题
- **RAPTOR**：递归摘要建树，兼顾细节与全局
- **元数据过滤**：先按时间/来源过滤再检索
- **重排 + 上下文压缩**：去掉无关句，省 token

---

## 四、评估（如何知道 RAG 好不好）

| 维度 | 指标/方法 |
|------|-----------|
| 检索质量 | Recall@k、MRR、NDCG |
| 生成质量 | Faithfulness（不幻觉）、Answer Relevancy、Context Precision/Recall（RAGAS） |
| 端到端 | 人工评估、LLM-as-Judge、线上 AB |

---

## 五、高频追问

**Q1：RAG 和微调怎么选？**
> 需「接入私有/时效知识 + 可溯源」→ RAG；需「改变模型行为/风格/能力」→ 微调。常结合：微调定能力，RAG 供知识。

**Q2：检索不准怎么优化？**
> 切片策略、换/微调 embedding、加 BM25 混合、加重排、query 改写、元数据过滤。先定位是「召回不足」还是「排序不对」。

**Q3：为什么需要重排（Rerank）？**
> 初检用 ANN 快但粗糙；rerank 用更贵但准的 Cross-Encoder 精排，用少量候选换质量大幅提升，性价比高。

**Q4：RAG 幻觉怎么治？**
> 要求「仅基于上下文」+ 片段引用 + 无检索则拒答 + Faithfulness 评测 + 关键事实抽取校验。
