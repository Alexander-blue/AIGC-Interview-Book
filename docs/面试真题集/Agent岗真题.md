# 🤖 Agent 岗真题（30+）

> 高频方向：Agent 架构、RAG、记忆、工具、MCP、多 Agent、工程化。覆盖算法应用 + 开发双视角。

---

## 一、Agent 范式
**1. 什么是 AI Agent？核心组成？**
> LLM（大脑）+ 规划 + 记忆 + 工具 + 反思。让模型能多步完成目标、调用外部。

**2. ReAct 的工作循环？**
> Thought → Action → Observation 循环；每步基于观察动态决策，强交互。

**3. 为什么选 ReAct 而不是 Plan-and-Execute？**
> 实时/动态/工具调用 → ReAct；长链可规划任务 → Plan-and-Execute。常「Plan 打底+ReAct 执行+Reflexion 纠错」。

**4. Reflexion 是什么？**
> 执行后自我反思失败原因，写入记忆，下一轮改进；适合可验证/迭代任务（代码）。

**5. Agent 最常见的失败场景？**
> 循环打转、幻觉工具参数、长上下文遗忘。对策：步数限制、循环检测、记忆写入、校验节点。

## 二、RAG
**6. RAG 解决什么痛点？**
> 知识过时、易幻觉、不可溯源。生成前先检索，可更新可溯源。

**7. RAG 标准流水线？**
> 切片→嵌入→存向量库→query嵌入→检索→重排→拼接→生成。

**8. 为什么需要重排（Rerank）？**
> 初检 ANN 快但粗；Cross-Encoder 精排用少量候选换质量大升。

**9. 混合检索为什么更好？**
> 向量弱精确词、BM25 强精确匹配；RRF 融合互补，召回更佳。

**10. RAG vs 微调怎么选？**
> 私有/时效知识+溯源 → RAG；改行为/风格/能力 → 微调。常结合。

**11. RAG 幻觉怎么治？**
> 仅基于片段 + 出处 + 无检索拒答 + Faithfulness 评测。

**12. 检索不准怎么优化？**
> 切片/换 embedding/加 BM25/重排/query 改写/元数据过滤；先定位召回还是排序问题。

## 三、记忆与工具
**13. 短期 vs 长期记忆？**
> 短期：上下文窗口/滑窗；长期：向量库/摘要/结构化存储，跨会话持久。

**14. Function Calling vs Tool Use？**
> FC：JSON Schema 标准、易实现；Tool Use：灵活、可并行、元数据多。简单用 FC，复杂用 Tool Use。

**15. 如何优化工具选择准确性？**
> 清晰工具描述/参数示例、few-shot、候选过滤、错误反馈学习。

**16. 如何防御提示注入？**
> 工具返回当不可信数据隔离、不执行其中指令、清洗、高危操作加权限/人工确认。

**17. 工具调用失败怎么办？**
> 重试+错误回灌模型自修正、备用工具、超时/资源限制、降级告知。

## 四、MCP 与多 Agent
**18. MCP 解决什么？**
> 工具/数据源与 Agent 强耦合、无法复用；用标准协议解耦，一次开发多端复用。

**19. 多 Agent 协作模式？**
> 主管-下属、流水线、辩论评审、角色扮演；通信用消息/共享记忆。

**20. 多 Agent 一定更好吗？**
> 否。增成本复杂度，仅「需分工/并行/专业化」时收益明显；常先问单 Agent 能否解决。

**21. 多 Agent 冲突怎么解？**
> 主管仲裁、评审/投票、共享一致记忆、明确职责边界。

## 五、工程化与评估
**22. Agent 上线最大坑？**
> 不可控（长链路任一环失败/幻觉）、成本难预测、难评测。解法：降级+追踪+回归评测+成本监控。

**23. 怎么做 Agent 回归测试？**
> 固化任务集与期望轨迹/结果，每次改动跑回归；LLM-as-Judge 评质量；监控线上漂移。

**24. 模型路由怎么设计？**
> 按复杂度路由：分类用小模型，推理用大模型；置信度/失败率动态调整，平衡成本质量。

**25. 如何降本？**
> 语义缓存、小模型路由、上下文压缩、批处理/异步。

**26. 可观测比普通应用多了什么？**
> token 用量、延迟分解（首 token/总）、幻觉率、评测分、Prompt 版本、降级次数、成本。

## 六、场景题
**27. 设计一个企业客服 Agent？**
> 意图识别→RAG 查知识库→ReAct 调用工单/查询工具→记忆用户上下文→人工兜底。重排+溯源+降级+权限。

**28. 长对话 Agent 怎么不丢信息？**
> 滑窗+摘要压缩+长期记忆检索；关键事实显式提取存库，按需拉取。

**29. Agent 怎么保证回答可靠？**
> 多步校验节点、工具结果验证、关键动作人工确认、评测闭环、不轻信单步输出。

**30. 自研核心循环还是用框架？**
> 原型用框架快；生产多数自研（ReAct 几十行）更可控/好调试/成本低。

**31. 如何评估一个 Agent 系统？**
> 单工具（正确率）、轨迹（合理性）、结果（成功率/LLM-Judge）、系统（延迟/成本/可靠），基准 AgentBench/WebArena/GAIA。
