# 🤖 03 · Agent 工程实践（动手篇）

> 从 0 搭一个生产可用的 Agent。原理见 `03-AI Agent`，本篇侧重「可运行的工程实现」与避坑。

---

## 一、最小可用 Agent（MVP）

```
1. 定义工具（函数 + JSON Schema 描述）
2. 主循环：
   - 把 system + 历史 + 工具描述 + 用户输入 给 LLM
   - 解析 LLM 输出：要么 Final Answer，要么 tool_call
   - 执行工具 → 结果回灌 → 继续循环
   - 达最大步数或得到答案则结束
3. 加记忆（短期窗口 + 长期向量检索）
4. 加可观测（记录每步轨迹）
```

**核心循环不过 50 行代码**——别被框架吓到。

## 二、工程化关键点（生产必做）
- **流式**：边思考边把中间过程/最终答案推前端（SSE）
- **中断/取消**：用户可中止长任务
- **工具安全**：危险操作确认、权限、超时、资源限制
- **错误恢复**：工具失败 → 错误回灌模型自我修正 → 重试/降级
- **上下文管理**：长对话摘要压缩、只留相关记忆
- **模型路由**：简单任务小模型，复杂才上大模型

## 三、常见失败模式与对策
| 失败 | 对策 |
|------|------|
| 循环打转 | 最大步数、循环检测、把关键结果写记忆 |
| 工具参数错 | schema 校验 + 类型转换 + 示例 |
| 幻觉工具名 | 工具描述清晰 + 候选过滤 |
| 上下文爆 | 摘要压缩 + 检索式记忆 |
| 成本失控 | 模型路由 + 缓存 + 步数限制 |

## 四、可观测与评测
- 全链路 trace（每步 thought/action/observation/token/耗时）
- 固化任务集做回归（改 Prompt/模型后跑评测）
- LLM-as-Judge 评最终质量 + 成功率指标

## 五、高频追问
**Q1：自研核心循环还是用框架？**
> 原型用框架快；生产多数场景自研核心循环（ReAct 不过几十行）更可控、好调试、成本低。框架适合快速验证或复杂组件复用。

**Q2：Agent 上线最大的风险？**
> 不可控性（长链路任一环失败/幻觉）、成本难预测、难评测。靠降级 + 全链路追踪 + 回归评测 + 成本监控化解。
