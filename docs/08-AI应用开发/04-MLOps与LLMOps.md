# 🔁 04 · MLOps 与 LLMOps

> 让 AI 系统「可迭代、可回滚、可监控」的工程体系。没有它，每次改模型都是盲飞。

---

## 一、MLOps（传统 ML 生命周期）
- **数据**：版本管理（Data Version Control）、质量监控、漂移检测
- **训练**：实验追踪（MLflow）、可复现、超参管理
- **部署**：模型注册、AB、金丝雀、回滚
- **监控**：预测质量、数据漂移、性能

## 二、LLMOps（大模型特化）
相比 MLOps 新增：
- **Prompt 版本管理**：Prompt 即代码，需版本化、灰度、回滚
- **模型注册与路由**：多模型/多版本管理、流量切分
- **评测闭环**：固化评测集 + 自动打分（RAGAS/LLM-as-Judge），改必测
- **成本可观测**：token 计量、调用分布、异常高成本告警
- **推理服务运维**：GPU 调度、KV Cache、连续批处理（见 `07-运维`）

## 三、CI/CD for AI
- 代码 CI + 数据校验 + 评测回归 + 自动部署
- Prompt/模型变更走评审 + 灰度 + 监控

## 四、数据闭环（持续提升）
```
用户反馈/线上结果 → 收集难例 → 标注/合成 → 微调/知识库更新 → 评测 → 发布
```

## 五、高频追问
**Q1：LLMOps 比 MLOps 多了什么？**
> Prompt 版本管理、模型路由与灰度、评测闭环（LLM-as-Judge）、成本可观测、推理服务（GPU/KV Cache）运维。模型本身往往不重训，重 Prompt/知识库迭代。

**Q2：怎么保证每次改 Prompt 不退化？**
> 维护评测集 + 自动化评测门禁，指标未达标阻断发布；Prompt 版本化可一键回滚；灰度小流量验证再全量。
