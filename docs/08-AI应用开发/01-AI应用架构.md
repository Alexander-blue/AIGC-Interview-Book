# 🏗️ 01 · AI 应用架构

> 一个生产级 AI 应用长什么样？如何选型？私有化还是云？本篇给全局视图。

---

## 一、典型分层架构

```
接入层：Web/App/API/IM 机器人
   ↓
网关层：鉴权 · 限流 · 成本统计 · 模型路由 · 降级
   ↓
编排层：Prompt 管理 · RAG · Agent · 多轮对话状态
   ↓
模型层：LLM（自部署 vLLM / 云 API）· Embedding · 重排 · 多模态
   ↓
数据层：向量库 · 关系库 · 对象存储 · 文档 ETL
   ↓
支撑：可观测 · 评测闭环 · 缓存 · 异步任务
```

## 二、关键技术决策

### 1. 模型从哪来？
| 方式 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| 云 API（GPT/Claude/Qwen云） | 快、免运维、能力强 | 数据出域、按量付费、不可微调 | 快速验证、非敏感 |
| 自部署开源（vLLM+Qwen/DeepSeek） | 数据私有、可控成本 | 需 GPU/运维 | 数据敏感、规模大 |
| 混合 | 主力闭源 + 开源兜底 | 复杂 | 生产稳健 |

### 2. 私有化 vs 公有云
- 数据合规/隐私要求高（金融/政企/医疗）→ 私有化（信创、离线）
- 初创/快速验证 → 公有云起步，后迁移

### 3. 框架选型
- **轻量自研核心循环**：多数场景够用、可控、易调试
- **LangChain/LlamaIndex**：快速原型，但生产注意抽象开销
- 不要为了用框架而用框架

## 三、常见反模式（避坑）
- 把全部逻辑塞进一个超长 Prompt
- 无降级：模型挂则全站挂
- 无缓存：重复请求狂烧钱
- 无评测：改 Prompt 不知道变好变坏
- 忽视安全：工具调用无权限、RAG 越权

## 四、高频追问
**Q1：什么时候该自部署而不是调 API？**
> 数据敏感/合规要求、调用量大到 API 成本过高、需微调/定制、需离线运行。否则先用 API 快速验证 PMF 更划算。

**Q2：AI 应用架构最易漏的环节？**
> 可观测与评测闭环、降级与成本治理、安全与权限。demo 阶段都无所谓，一上生产就爆。
