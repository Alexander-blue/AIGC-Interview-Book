# 🧪 03 · 测试（含 AI 评测）

> 传统测试保「功能正确」；AI 测试还要保「输出质量稳定」。这是 AI 应用质量保障的难点。

---

## 一、传统测试
- **单元测试**：函数/模块正确性（pytest/JUnit/Go test）。
- **接口测试**：API 契约、边界、异常。
- **性能测试**：压测（QPS、延迟、P99）、容量规划。
- **E2E/UI 测试**：关键流程自动化。

## 二、AI 应用测试的特殊性
- **非确定性**：同输入模型输出可能不同 → 不能简单 assert 相等，用「评测指标 + 容忍窗口」。
- **质量回归**：模型/ Prompt 一改，质量可能悄悄下降 → 需**评测集 + 自动化打分**（RAGAS / LLM-as-Judge）。
- **幻觉/安全测试**：构造对抗 case，验证不胡说、不越权。
- **RAG 测试**：检索召回率、生成忠实度分开测。

## 三、治理
- 固化「黄金测试集」，每次发布跑回归。
- 灰度发布 + 在线 AB + 监控告警。
- Prompt/模型版本化，可回滚。

## 四、高频追问
**Q1：AI 输出不确定，怎么写测试？**
> 不测「逐字相等」，测「属性」：用评测集+自动打分（如 LLM-as-Judge）检查正确性/相关性/格式；对关键逻辑用确定性 mock 模型。

**Q2：怎么防 Prompt 改坏效果？**
> 维护质量评测集，CI 中跑自动化评测；关键指标设阈值，未达标阻断发布；做 Prompt 版本管理与灰度。
