# 🗄️ 02 · 后端（AI 服务架构）

> AI 应用的后端不是普通 CRUD——要管模型调用、流式、缓存、成本、权限。本篇讲 AI 后端的设计要点。

---

## 一、核心考点（通用）
- **架构**：分层、微服务、DDD、事件驱动。
- **API**：REST / gRPC、鉴权（JWT/OAuth）、限流、幂等。
- **数据库**：关系型（PostgreSQL/MySQL）、NoSQL（MongoDB/Redis）、选型。
- **缓存**：Redis 命中率、击穿/雪崩/穿透。
- **消息队列**：Kafka/RabbitMQ，异步解耦。

## 二、AI 后端专属设计
- **模型网关**：统一封装多家 LLM API，做路由/降级/成本统计。
- **流式转发**：后端消费上游 SSE，转给前端（见 `06-Java`/`04-Go`）。
- **Prompt/知识库管理**：模板存储、版本、AB；文档 ETL 管线。
- **多租户与权限**：隔离不同客户的语料/对话（RAG 安全关键）。
- **成本控制**：token 计量、配额、缓存重复请求。
- **异步任务**：长任务（文档入库、批量推理）用队列 + 状态轮询。

## 三、高频追问
**Q1：AI 后端和普通后端最大区别？**
> 多了「不确定性 + 高延迟 + 高成本」：模型调用慢且贵、结果非确定性，需要流式、缓存、降级、成本计量与并发控制，普通 CRUD 没有这些。

**Q2：怎么做 LLM 调用的缓存降本？**
> 语义缓存（相似问题复用答案）、精确缓存（相同 prompt 命中）、热点知识预生成；配合模型路由（小模型处理简单问题）。

**Q3：RAG 的多租户怎么隔离？**
> 向量库按 tenant_id 过滤/独立 collection、行级权限、对话与文档归属校验，防止跨客户数据泄漏。
