# 🖼️ 03 · 多模态与语音生成

> 「看、听、说」的能力：VLM（视觉语言模型）、文生图/视频、TTS 语音合成。

---

## 一、多模态大模型（VLM）

**目标**：让 LLM 理解图像/视频，并能图文混合推理。主流架构：

1. **视觉编码器**（ViT/CLIP Image Encoder）把图像编码为视觉 token
2. ** projector/Adapter**（如 MLP、Q-Former）把视觉 token 对齐到文本空间
3. **LLM** 接收「文本 token + 视觉 token」做统一推理

代表：LLaVA（简洁对齐）、Qwen-VL、GPT-4V、Gemini（原生多模态）。

**训练两阶段**：先对齐（冻 LLM，训 projector）+ 再指令微调（解冻端到端）。

---

## 二、文生图 / 文生视频

- **文生图**：CLIP 文本编码器 → 条件注入 Diffusion（见 `01-Diffusion`）。代表 Stable Diffusion、DALL·E、Midjourney。
- **文生视频**：在时空上扩展 Diffusion（3D U-Net / 时空注意力），或自回归逐帧生成。代表 Sora（扩散 transformer DiT）、Runway、可灵。

**难点**：时序一致性、运动合理性、长视频连贯、算力昂贵。

---

## 三、语音生成（TTS / 语音大模型）

- **传统 TTS**：文本前端 → 声学模型（FastSpeech）→ 声码器（HiFi-GAN）合成波形。
- **神经 codec + LLM**：把语音离散化为 token（如 EnCodec），用 LLM 做「语音自回归生成」，实现自然语音/克隆/情感。代表 VALL-E、ChatTTS。
- **语音理解**：Whisper（ASR）、语音大模型（GPT-4o 类原生语音）。

---

## 四、跨模态对齐的本质

> 多模态的核心难题是**表征对齐**——让「猫的图像 token」和「'猫'的文本 token」在 LLM 空间里靠近。CLIP 用「图文对比学习」解决了第一步，后续工作都在做「更好的对齐 + 更紧的融合」。

---

## 五、高频追问

**Q1：LLaVA 为什么训 projector 而不是直接冻视觉编码器？**
> 视觉特征与文本空间维度/分布不同，需一个可学习的适配器把视觉 token 映射进 LLM 可理解的空间；先冻 LLM 保语言能力的稳定，再微调融合。

**Q2：文生视频比文生图难在哪？**
> 多了时间维，要保时序一致与运动合理；显存/算力随帧数线性涨；长视频连贯难。

**Q3：VALL-E 类语音 LLM 的 idea 是什么？**
> 用神经 codec 把语音变离散 token，再用 LLM 自回归生成语音 token，最后解码回波形，实现「像生成文字一样生成语音」。
